# 修訂規格書 R1 — 對對齊精修、檢閱工具與呈現強化

> 狀態：`ready-for-agent` ｜ 前置：`tunnel-viewer-mvp.md`（MVP 已實作）
> 來源：第二輪需求拷問會議共識
> 範圍：隧道資訊面板、重新對齊、錨點模型改版、待檢查處理、群組合併、原圖檢視、照片旋轉

---

## Problem Statement

MVP 上線實際使用後暴露五個缺口：

1. **匯入報告是一次性的**：Δt 表、缺照分佈等關鍵資訊只存在於建立精靈的暫存狀態，重新整理即消失，事後無從查閱。
2. **容差焊死**：時間容差只在匯入時設定一次，事後無法評估「不同容差會得到什麼結果」，也無法重新對齊。
3. **待檢查沒有下文**：旗標照片只能看不能處理；相鄰的拆裂群組（同一快門被切成兩群）也沒有合併手段。
4. **看不了原圖**：只有 1600px 縮圖，牆面細裂縫需要原始解析度＋逐像素放大。
5. **方向錯了沒救**：機位裝設方向與照片實際方向不符時無法修正；同機位偶有幾張比例異常的照片也無個別調整。

## Solution

以「**隧道資訊面板**」為中樞新增四個能力，並重構錨點綁定模型：

- **資訊面板**：持久化的匯入報告（Δt 表、缺照分佈、容差）、待檢查清單、已改判缺照清單、相機旋轉設定、重新對齊入口。
- **重新對齊**：輸入新容差 → 乾跑預覽統計 → 確認後僅重建群組歸屬。因為錨點改綁**照片**，重新對齊後錨點自動落位、零遺失。
- **錨點模型 v2**：錨點 = 載體照片 + 里程絕對值。載體失效時自動轉移；整組無照片時退回時間最近群組並標警示。
- **檢閱模式**：三聯並排比較相鄰群組，支援合併（含衝突裁決），鍵盤驅動。
- **呈現強化**：全螢幕原圖檢視（逐像素縮放）；三層優先序的旋轉體系（單張手動 > 機位預設 > EXIF 自動），比例異常的照片格直接浮現旋轉按鈕。

## User Stories

### 隧道資訊面板

1. As 檢測人員, I want 在檢視器內開啟「隧道資訊」面板看到當年匯入時的完整報告（各機 Δt、容差、群組數、缺照分佈）, so that 換電腦或隔月回來仍能掌握這條隧道的對齊品質。
2. As 檢測人員, I want 面板顯示目前生效的容差值, so that 我知道現在的群組是在什麼假設下產生的。
3. As 檢測人員, I want 面板列出所有相機及其旋轉設定並可直接修改, so that 方向修正在任何階段都做得到。

### 重新對齊

4. As 檢測人員, I want 輸入一個新的時間容差後先看到乾跑預覽（新容差下的群組數、缺照分佈、待檢查數）而不寫入, so that 我能比較不同容差的品質再決定。
5. As 檢測人員, I want 比較滿意後按「套用」才真正重建群組, so that 不滿意就取消、零風險。
6. As 檢測人員, I want 重新對齊後我打過的所有里程錨點自動跟著照片落到新群組、一個都不掉, so that 精修對齊不需要重打全線錨點。
7. As 檢測人員, I want 重新對齊完成後全線推算里程立即重算且其他開著同一隧道的畫面同步更新, so that 協作者不會看到過期資料。

### 錨點模型 v2

8. As 檢測人員, I want 錨點清單顯示每個錨點的載體相機與所在群組, so that 我知道這個絕對值是釘在哪張照片上。
9. As 檢測人員, I want 承載錨點的照片被改判缺照時，錨點自動轉移給同群組下一台有影像的相機, so that 改判不會誤殺錨點。
10. As 檢測人員, I want 若某錨點所屬群組整組都沒有影像了，錨點退回時間最近的群組並在清單中亮警示, so that 資料永不靜默消失。
11. As 使用舊資料庫的人員, I want 開啟既有隧道時自動升級錨點結構（載體＝該群組第一張照片）而內容完全不變, so that 升級無感。

### 待檢查處理

12. As 檢測人員, I want 面板的待檢查清單逐筆列出原因（EXIF 缺漏／對齊殘差）並可跳轉至該群組, so that 我能逐一複核。
13. As 檢測人員, I want 對每筆待檢查按「✅ 確認無誤」清除旗標, so that 複核過的不會反覆出現。
14. As 檢測人員, I want 對每筆待檢查按「⛔ 改判缺照」讓該槽位顯示為無影像, so that 明確壞掉的照片不占據矩陣格子。
15. As 檢測人員, I want 「已改判缺照」區塊列出所有被我改判的照片並可復原, so that 手滑有補救管道。
16. As 檢測人員, I want 改判缺照的照片在日後重新對齊時仍然被排除, so that 我的判斷跨對齊持續有效。

### 群組合併

17. As 檢測人員, I want 從待檢查清單點「🔍 檢閱邊界」或平時按 `M` 進入檢閱模式, so that 判斷拆裂群組不必離開工作流。
18. As 檢測人員, I want 檢閱模式以前一群組｜當前｜後一群組三聯並排、同相機橫向對齊並標註毫秒級校正時間差, so that 一眼看出是不是同一快門被拆成兩組。
19. As 檢測人員, I want 按 `⇤ 與前合併` 或 `與後合併 ⇥` 把隔壁群組併入當前, so that 序列恢復正確。
20. As 檢測人員, I want 合併造成同機兩張時彈出選擇框讓我保留左邊或右邊那張、落選的自動改判缺照, so that 鐵律（每機每群一張）不被破壞。
21. As 檢測人員, I want 合併後群組編號重排但錨點完全不受影響, so that 合併是安全的日常操作。

### 原圖檢視

22. As 檢測人員, I want 點擊任一照片格開啟全螢幕覆蓋層載入原始解析度, so that 牆面細微裂縫看得清楚。
23. As 檢測人員, I want 全螢幕中滾輪以游標為中心逐像素放大、拖曳平移、雙擊切換適合／100%, so that 檢查體驗專業流暢。
24. As 檢測人員, I want 全螢幕中按 `Tab` 切換同一群組的其他相機視角、`Esc` 關閉, so that 不離開覆蓋層即可交叉比對。

### 照片旋轉

25. As 檢測人員, I want 建立精靈步驟二為每台相機選擇初始旋轉（0/90/180/270）, so that 裝反的機位第一次匯入就是對的。
26. As 檢測人員, I want 日後在資訊面板修改任一相機的旋轉且縮圖快取自動失效重生成, so that 修正不需要重建專案。
27. As 檢測人員, I want EXIF Orientation 永遠自動尊重, so that 相機豎拍的照片天生就是正的。
28. As 檢測人員, I want 比例異常的照片格上直接出現旋轉按鈕、按一下轉 90 度並記住在那一張上, so that 少數派照片不用進任何設定頁就能修。
29. As 檢測人員, I want 全螢幕原圖檢視中按 `R` 同樣可旋轉當前照片, so that 放大確認後就地修正。
30. As 檢測人員, I want 匯入分析時自動比對每張照片與該機位多數派的比例、把少數派標示出來, so that 異常照片自己浮上來而不是靠我逐張找。

## Implementation Decisions

### 錨點模型 v2（本修訂的核心前置）

- `anchors` 表改為 `carrier_photo_id（UNIQUE FK → photos.id）+ mileage_m`。語意：「這張照片拍到的實體里程碑位於 X 公尺」。
- **解析鏈**：載體照片 → 其 `group_id` → 群組 `seq`。推算里程、單調防呆、Enter 編輯判定全部走此解析，不再儲存 seq。
- **載體轉移**：改判缺照若涉及載體照片 → 自動轉移給同群組下一台（camera_seq 順序）有影像且未改判的照片；整組皆無 → 錨點保留、解析時退回**時間最近群組**並在清單標 `⚠ 失準警示`。
- **單一群組唯一性**：DB 層唯一約束在 photo_id；應用層驗證先解析到群組再執行既有的嚴格單調檢查（`interp.check_anchor` 不變）。
- **Enter 語意不變**：當前群組已有錨點（解析判定）→ 編輯該錨點；否則新建，載體自動取該群組第一台有影像的相機照片。
- **遷移**：各隧道 db 的 `meta.schema_version` 記錄版本；v1（group_seq 綁定）開啟時自動升級——每個舊錨點指定該群組第一張照片為載體，數值不變。

### 重新對齊

- `POST /api/tunnels/{tid}/realign {tolerance}`：乾跑——用 photos 表既存的原始 EXIF 時間（排除 `manual_missing=1` 者）重跑對齊引擎，回傳與匯入預覽同構的統計（含 Δt 表），**不寫入**。
- `POST /api/tunnels/{tid}/realign/apply {tolerance}`：交易內重建 `photo_groups` 與 `photos.group_id`；殘差旗標依新配對重算；手動缺照維持排除；`est_mileage_m` 以既有錨點（經解析鏈）重算；更新報告 JSON；廣播 `realigned` 事件，前端清空群組快取並重抓。
- 對齊引擎本身不改——重新對齊就是對既有照片集合再呼叫一次。

### 待檢查 / 改判

- `photos` 新增欄位：`manual_missing INTEGER DEFAULT 0`、`width`、`height`（匯入時量測，EXIF orientation 套用後的顯示尺寸）。
- `POST .../photos/{pid}/confirm_flag`：`flagged=0`。
- `POST .../photos/{pid}/mark_missing`：`manual_missing=1`、`group_id=NULL`；觸發載體轉移；群組 `missing_count` 重算；廣播。
- `POST .../photos/{pid}/restore`：`manual_missing=0`，指派回時間最近的現存群組。
- 重新對齊時 `manual_missing=1` 者一律排除——使用者意圖跨對齊持續。

### 群組合併

- `POST /api/tunnels/{tid}/groups/{seq}/merge {direction: prev|next, keep?: current|neighbor}`：
  - 無衝突（合併後無同機雙張）→ 直接合併：鄰組照片全部改掛當前群組、鄰組刪除、其後 seq 整體前移。
  - 有衝突且未指定 `keep` → 回 `409` 附衝突相機清單；前端彈保留選擇框後帶 `keep` 重送；落選照片走改判缺照流程。
- 因錨點綁照片，seq 重排零影響；合併後重算 est、廣播 `merged`。
- **不做復原**——操作罕見且需明確確認，誤併可手動重打錨點／重新對齊兜底。

### 隧道資訊面板

- 匯入報告以 JSON 存於隧道 db（meta 表 `import_report` 鍵）：Δt 表、容差、群組數、缺照分佈、待檢查數、比例異常清單；每次匯入／重新對齊後更新。
- `GET /api/tunnels/{tid}/info`：聚合 meta、報告、待檢查清單（含原因）、已改判清單、相機旋轉設定、失準警示錨點。
- 建立成功後嚮導分頁自動關閉（行為微調）；自動跳轉檢視器維持現狀。

### 旋轉體系（優先序：單張 > 機位 > EXIF）

- `cameras.rotation INTEGER DEFAULT 0 CHECK(0/90/180/270)`；`photos.rotation_override INTEGER NULL`。
- 顯示合成：`exif_transpose(img)` 永遠先套 → 再套 `override ?? camera.rotation`。
- 縮圖生成套用相同合成；旋轉變更時刪除該隧道（或該照片）的 `.thumb_cache` 檔案使其重生。
- `PUT .../cameras/{seq} {rotation}`、`PUT .../photos/{pid}/rotation {angle}`，皆廣播 `photo_updated` / `camera_updated`。
- **比例異常偵測**：匯入時計算每張照片套用 EXIF＋機位旋轉後的顯示寬高比，與該機位多數派比較，少數派列入報告；前端網格中，異常且尚無 override 的照片格右上角顯示 ⟳ 按鈕，按一下 +90° 並持久化到該照片；全螢幕原圖檢視中 `R` 同效。

### 原圖檢視覆蓋層

- 點擊照片格 → 全螢幕覆蓋層，載入無 `w` 參數的原圖串流。
- 互動：滾輪以游標為中心放大（上限約 8×原生）、拖曳平移、雙擊切換適合視窗／100%、`Tab` 循環同群組其他相機、`R` 旋轉、`Esc` 關閉。
- 大圖載入期間顯示低解析度模糊墊底（既有 1600px 縮圖）。

### 快捷鍵增補

| 鍵 | 場景 | 動作 |
|---|---|---|
| `M` | 檢視器 | 進出檢閱模式（三聯比較） |
| `⇤` / `⇥`（自訂鍵） | 檢閱模式 | 與前／後合併 |
| `Tab` | 原圖覆蓋層 | 切換相機視角 |
| `R` | 原圖覆蓋層 | 旋轉當前照片 |

## Testing Decisions

延續既有三縫（對齊引擎、內插防呆、API 整合），本期測試集中在 API 整合縫與一個新的純邏輯縫：

1. **錨點解析鏈（純函式核心）**：載體→群組解析、載體自動轉移、整組無影像時的時間就近退回與警示標記、舊版遷移的正確性。這是本期正確性核心，測試密度最高。
2. **API 整合（FastAPI TestClient + 暫存目錄）**：
   - 重新對齊：乾跑不寫入；apply 後錨點經照片解析全數存活且 est 正確；manual_missing 跨對齊持續排除。
   - 合併：無衝突直合；409 衝突→帶 keep 重送→落選者變 manual_missing；seq 重排後窗口查詢與錨點解析一致。
   - 旋轉：EXIF orientation fixture（Pillow 可寫 tag 274）＋機位＋單張 override 三層合成的最終尺寸斷言；快取失效（改旋轉後同 URL 內容改變）。
   - 改判/復原：missing_count 變化、restore 回時間最近群組。
3. **前端**：手動驗收為主；E2E 腳本擴充場景（重新對齊流程、合併流程、旋轉按鈕）沿用 `e2e_check.py` 模式。

Prior art：`test_api.py` 的錨點 CRUD 與 WS 廣播測試、`test_align.py` 的對齊 fixture 工廠。

## Out of Scope

- 合併／刪除的復原（undo）
- 任意角度旋轉（僅 90° 步進）
- 手動分割群組（交由重新對齊＋容差解決）
- 全自動旋轉少數派照片（決策：必經人工按下旋轉）
- 真瀏覽器新分頁開原圖（採覆蓋層方案）
- 重新對齊時變更相機資料夾組成（增減相機仍＝開新專案）

## Further Notes

- Q9 使用者語意「按了以後 都旋轉」解讀為：按旋轉鈕後**該張照片**旋轉 90° 並持久化；若實測後發現使用者意指「整機位一起轉」，機位旋轉設定已在面板提供等效操作。
- 重新對齊的 apply 在 WAL 下對讀者無阻塞；apply 完成的廣播會讓所有客戶端清快取重抓，短暫重新載入屬預期行為。
- 迁移失敗（如 photos 表為空卻有錨點）時保留原狀並在服務日誌報錯，不靜默丟資料。
